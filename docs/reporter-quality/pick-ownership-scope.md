# E25: historical scope of pick-inventory evidence

A frozen ownership view can be reproducible without establishing who owned a
pick at an earlier reporting cutoff. The current projection starts from original
owners and overlays the selected traded-picks endpoint; it does not reconstruct
ownership from the sequence of dated completed transfers. Retrospective replay
can therefore expose later ownership through an earlier week's inventory view.

The candidate keeps every source value, identity, field path and temporal field.
It adds a scoped limitation to roster-inventory summaries, including empty pick
lists, and individual pick rows. It also describes the snapshot as selected for
the reporting cutoff, rather than claiming that selection proves the time of
observation. Player records do not inherit the inventory caveat, and dated trade
assets remain separate evidence. The tool implementation version is incremented
so prepared tool definitions recognize the presentation change.

This is disclosure of a source limitation, not ownership reconstruction. It does
not assert that every ownership row is wrong. Absence of a recorded seasonal
transfer cannot rule out preseason or otherwise missing history. In particular,
a reporter must not replace an uncertain current owner with the original owner
merely because it cannot find a transfer. Arbitrary SQL output retains its
existing generic SQL limitations; this candidate covers curated roster evidence.

## Validation and proposed comparison

Twenty-seven targeted offline checks pass across the new scope tests, evidence
overviews and executed-evidence integration tests. They cover unchanged source
values and bindings, empty inventory, pagination, unrelated player and standings
records, and dated transaction assets. These are implementation checks, not proof
that a reporter handles uncertainty well.

E25 is preregistered as two complete Week 3 reporting arms from the same original
Week 2 memory checkpoint and original pre-generation embeddings. The baseline is
the merged E16 runtime. The E24 record-verification candidate and the rejected
storyline or review-receipt treatments are not included. Original requests,
source cutoffs, prompts, model settings and memory behavior remain matched.

Both arms must encounter pick-inventory evidence. A favorable result requires the
treatment to qualify or avoid an unsupported historical inventory or resource
constraint asserted by fresh control, while preserving supported dated transfers.
No inventory exposure, both arms qualifying appropriately, or no analogous
opportunity is inconclusive. No favorable rerolls or source regeneration are
permitted. Article and memory changes will be assessed separately, and behavior
before the caveat is encountered will not be attributed to it.

## Completed E25 comparison

Both arms completed article submission and memory closeout. Control used 28 calls
and ten edits; treatment used 36 calls and six edits. The pair cost $0.255850584,
with no new uncertain request or embedding call. Both preserved all 22 original
memory versions and valid evidence bindings, with no duplicate trade identity.

Control never used roster inventory, so the primary both-exposure discriminator
was unavailable and the comparative efficacy result is inconclusive. Treatment
did encounter inventory twice. Its trace explicitly recognized the caveat,
rejected a precise historical-inventory assertion, and relied on dated transfers
instead; the final article retained those recorded movements. That is observed
compliance with the caveat, not proof that this candidate outperformed control.

Treatment also encountered a SQL permission rejection and corrected two memory
argument rejections. It continued an inherited storyline whose original identity
was already mixed and shifted; no general lifecycle or prose improvement is
claimed. No reroll or full-season promotion follows this pair. The candidate
remains reviewable for accurate source-scope disclosure, with broader behavioral
efficacy unresolved.
